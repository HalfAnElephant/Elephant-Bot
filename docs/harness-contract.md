# Pi harness contract

The pinned npm Pi 1.5.0 RPC executable is invoked through an absolute argv. A TaskRun owns one process and an exact JSONL session path. Ambient HOME, credentials, extensions, context files, skills, MCP and prompt templates are excluded. Research mode enables only the explicitly installed `research_extension.ts` tools. Built-in tools, including bash, remain disabled.

The stdout reader starts before prompt submission. Records split on LF bytes, preserving Unicode U+2028/U+2029. Events are limited to 2 MiB and the queue to eight records. stderr is drained with a 20 MiB ceiling. Truncated/malformed/oversized records fail the run. Prompt ACK and `agent_end` cannot complete it. `handled` fails explicitly. `agent_settled` requires a final assistant message with no error. Core additionally requires a verified archive manifest and retrieved source evidence before research success.

Cancellation revokes the local run capabilities, sends `clear_queue` followed by `abort`, waits briefly, then terminates and kills the process group. Parent exit plus group disappearance is checked. The direct local runner has no verified cgroup boundary. Unconfirmed stop retains the persistent slot and enters reconciliation. The supervisor renews every ten seconds with a thirty-second lease and uses a conservative twenty-five-second local authority window. Every model/tool operation rechecks Core authority. New operations fail closed when Core is unavailable. An already dispatched upstream model request can still consume provider usage.

Capabilities declare event streaming, cancellation and session persistence. Append-input, interactive questions and exact session resume are disabled. Saved exact session references support inspection and future explicit recovery. The implementation never uses fuzzy `--continue` or blindly resends an uncertain prompt.

## Research capabilities

Each run receives separate random model and tool tokens. The runner has no provider master key. The trusted supervisor fixes the upstream endpoint and approved model, limits thirty model calls, sixty tool calls, a 2 MiB model request/response and 4096 output tokens per call. Requests are serialized for quota reservation. Streaming OpenAI-compatible responses are buffered within the limit and translated into bounded SSE. This proxy supports the validated chat-completions subset only.

Search uses a fixed public Bing RSS endpoint, accessed through the same public-address validation as fetch. Fetch accepts public HTTPS text sources on port 443. DNS answers must all be globally routable and the connection uses the checked IP with TLS hostname validation. Every redirect resolves and checks again, with three redirects, a 1 MiB page cap and identity encoding. Tools keep a host-owned retrieval ledger. Report writes accept a single filename under `outputs/`, UTF-8 Markdown, text or JSON, at most twenty files of 1 MiB each.

Export traverses workspace descriptors with `O_NOFOLLOW`, rejects non-regular and multiply linked files, enforces count/total limits, checks stable size/mtime, writes a supervisor archive, and computes hashes there. Core opens only UUID archive references and verifies actual size/hash. The internal Worker API is trusted to report source retrieval, process-group stop and archive provenance. Production mode uses a separate runner UID and fixed systemd launcher. Its root-owned stop evidence checks unit/cgroup termination. Each deployment target must run the isolation probe under umask 0077, including supervisor workspace access and detached-descendant termination.
