# 邮件触发草稿

本地阶段复用受认证的 Leader 和 `schedules.create` 保存未启用的邮件触发草稿。账号标识和文件夹是计划配置，不表示已验证或连接邮箱。草稿由原会话、用户与项目持有。

- `mail` 保存账号、文件夹及 `all`（全部）、`any`（至少一个）、`none`（全部排除）筛选组，支持发件地址/域名、主题、正文的精确或包含判断。
- `goal` 保存用户明确提出的执行要求；支持现有 `success_checks` 和 `requested_outputs`。不会把邮件正文拼进目标。
- 邮件草稿必须显式 `enabled=false`，没有下次触发时间。继续通过已有 schedules 接口查询、修改或删除；变更账号/文件夹或切换时间触发必须新建草稿。

生产启动仍没有邮箱账号配置、IMAP/SMTP、扫描游标、自动轮询或发送能力。只有测试进程显式注入严格绑定账号、文件夹、用户、身份、会话和项目的合成收信源时，才允许启用该合成规则。该测试在每条规则创建/重新启用时保存当前 UID 水位，命中后将游标、去重回执与普通任务提交写进同一事务；未命中只更新游标。任务执行权限重新检查合成绑定、回执与当前启用水位。邮件内容不送进任务上下文。本地集成用例对两种受限目标调用真实 Worker 的领取、运行编排、回执和归档流程；模型/Harness 输出为脚本化夹具，不执行真实模型或命令，不代表真实邮箱规则已上线。

自然语言接入验收使用模拟模型输出调用真实 Leader 与 SQLite，未验证真实模型自由生成参数或真实邮箱服务。
