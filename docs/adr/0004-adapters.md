# ADR 0004 — 双接入与投递不确定性

2026-11-08，接受。NapCat 服务端反向 WS，重复在线连接拒绝；连接代次和随机 echo 共同关联请求。断线缺口保留，不承诺历史补齐。官方 Webhook 使用 Ed25519 对 timestamp+原始body验签；op=13 challenge只签指定格式，不入Inbox。签名最大年龄初始300秒，可按平台重投实测调整。

平台消息先落 Inbox，再由后台 Core 消费。官方 @事件独立于文本判断；全量能力要求显式配置许可并观察到全量事件，或管理员记录的已有烟测。观察全量不授予主动发信。群、C2C、频道分别选择API。

统一端点根据现行官方文档为 api.bot.qq.com，token提前60秒刷新，合并并发请求。reply window=300秒/5次仅是带日期的待实测配置，不宣称所有surface相同。平台错误可进一步收紧。

Outbox 事务分配 msg_seq 并冻结，回执丢失/服务器不确定结果为UNKNOWN，不盲重试。超时任务保留可领取，普通闲聊过TTL丢弃。文本按1800字符分段，各段独立去重。媒体暂不自动下载以避免临时链接和不受控URL进入业务与产物路径。

正向 WebSocket 支持通过可选 `websocket_url` 启用，复用 DTO/Inbox/Outbox/echo/代次语义，启动先读 get_login_info 验证机器人身份。部署方根据现有 NapCat 服务选择连接方式，并显式配置目标白名单。
